Add what you have

The alarm clock is the core. Everything else is an integration that lights up when you have the device: a speaker, lights, a thermostat, a vacuum, cameras, AI. Missing one is never a problem.

Flight Day API 1.0 is the single planned public API: the model and five calls. Its one-page guide and demo-house checks are in development. Hub HTTP and client internals are private. Agent control is a separate contract, planned for Labs after launch.

Where this stands. The integrations below run in one household today, each with its status. The public extension API and Settings › Integrations are being developed for Flight Day for Home Assistant. In development

What Settings › Integrations will show

Each integration gets a status and a one-line summary. Green is on, muted is off, amber needs you, red is an error.

StatusWhenExample
OnTurned on, with every device it needs present and working“Weekdays 6:45 AM · Bedroom speaker · Bedroom lamp”
OffTurned off“Labs · automatic heat and cool, shadow first”
Needs setupOn, or about to be, but a device it needs is missing“Choose a thermostat”
UnavailableA device it uses is unavailable“Bedroom speaker unavailable · volume control off”
ErrorIts own code failed; Home Assistant gets a repair notice“Stopped after an error · see Home Assistant”

Your own integrations show On or Off, and Unavailable when they haven’t posted for longer than they promised (“No update since 6:10 AM”).

Build your own

Four small parts of Flight Day for Home Assistant, usable from automations, scripts or a custom integration, with no Flight Day code changes. In development

Role hints

Give an entity the Home Assistant label flightday_<role>, such as flightday_wake_lights, and it becomes a strong suggestion for that role. A crew member still confirms it; nothing is applied silently.

Lines

Post a short line to the briefing, Home or Night with flightday.post_line: up to 80 characters, with an end time. Night lines are text only; they never wake a screen or make a sound.

Checks

Report something that needs attention to the Systems check with flightday.report_check, as a Caution (attention) or a Warning (problem), optionally with a one-tap fix. Locks, alarm panels and thermostats can’t be fixes.

Register, and react

Register with flightday.register_integration when the flightday event says ready, and react to that event in automations: wake is liftoff, up is a confirmed “I’m up”.

Examples

Each example runs against Flight Day for Home Assistant (contract 3.0, Home Assistant 2026.1 or later). The examples are included with the open-source code. None has passed staging validation yet; each says so until it does.

Bin day

Staging validation: pending

Registers, then posts a line the evening before collection and clears it the next morning. A shorter variant is included; install only one.

bin-day/bin_day.yaml
# Append both entries to automations.yaml. Collection sensor: local YYYY-MM-DD.
- alias: Bin day register
  triggers:
    - trigger: event
      event_type: flightday
      event_data: {action: ready}
    # Registration is idempotent; double firing is harmless.
    - trigger: homeassistant
      event: start
  actions:
    - action: flightday.register_integration
      data: {id: bin_day, name: Bin day, provides: [lines]}

- alias: Bin day line
  triggers:
    - trigger: time
      at: "17:00:00"
      id: evening
    - trigger: time
      at: "09:00:00"
      id: morning
    # Catch-up: a post missed while Flight Day was reloading is restored when it is ready again.
    - trigger: event
      event_type: flightday
      event_data: {action: ready}
      id: catchup
    - trigger: homeassistant
      event: start
      id: catchup
  variables:
    collection: "{{ states('sensor.bin_collection_day') }}"
    eve: "{{ collection == (now().date() + timedelta(days=1)) | string and now().hour >= 17 }}"
    overnight: "{{ collection == now().date() | string and now() < today_at('09:00') }}"
  actions:
    - if:
        - condition: template
          value_template: "{{ trigger.id != 'morning' and (eve or overnight) }}"
      then:
        # Same key and until each time, so posting twice is harmless.
        - action: flightday.post_line
          data:
            source: x_bin_day
            key: recycling
            text: Recycling goes out tonight
            show: [briefing, home]
            priority: normal
            until: "{{ (today_at('09:00') + timedelta(days=1 if eve else 0)).isoformat() }}"
            icon: recycle
      else:
        - action: flightday.clear_line
          data: {source: x_bin_day, key: recycling}
bin-day/bin_day_minimal.yaml
- alias: Bin day minimal register
  triggers: [{trigger: event, event_type: flightday, event_data: {action: ready}}, {trigger: homeassistant, event: start}] # Registration is idempotent; double firing is harmless.
  actions:
    - action: flightday.register_integration
      data: {id: bin_day, name: Bin day, provides: [lines]}
- alias: Bin day minimal line

Filter reminder

Staging validation: pending

A Systems check finding raised as a Caution (attention) that clears by itself (ok), with no action.

filter-reminder/filter_reminder.yaml
- alias: Filter reminder
  mode: restart
  triggers:
    - trigger: event
      event_type: flightday
      event_data: {action: ready}
    # Registration is idempotent; double firing is harmless.
    - trigger: homeassistant
      event: start
  actions:
    - action: flightday.register_integration
      data: {id: filter_reminder, name: Filter reminder, provides: [checks]}
    - repeat:
        while: "{{ true }}"
        sequence:
          - if:
              - condition: template
                value_template: "{{ is_number(states('sensor.robot_vacuum_filter_days_remaining')) }}"
            then:
              - action: flightday.report_check
                data:
                  source: x_filter_reminder
                  key: filter_due
                  status: "{{ 'attention' if states('sensor.robot_vacuum_filter_days_remaining') | float <= 3 else 'ok' }}"
                  title: Robot vacuum filter
                  detail: "{{ 'Replace now' if states('sensor.robot_vacuum_filter_days_remaining') | float <= 0 else 'Replace in ' ~ (states('sensor.robot_vacuum_filter_days_remaining') | float | round(1)) ~ ' days' }}"
                  since: "{{ states.sensor.robot_vacuum_filter_days_remaining.last_changed.isoformat() }}"
                  morning: false
            else:
              - action: flightday.clear_check
                data: {source: x_filter_reminder, key: filter_due}
          - wait_for_trigger:
              - trigger: state
                entity_id: sensor.robot_vacuum_filter_days_remaining

Porch lights

Staging validation: pending

A Systems check finding with a one-tap Turn off action.

porch-lights-check/porch_lights.yaml
- alias: Porch lights check
  mode: restart
  triggers:
    - trigger: event
      event_type: flightday
      event_data: {action: ready}
    # Registration is idempotent; double firing is harmless.
    - trigger: homeassistant
      event: start
  actions:
    - action: flightday.register_integration
      data: {id: porch_lights_check, name: Porch lights check, provides: [checks]}
    - repeat:
        while: "{{ true }}"
        sequence:
          - if:
              - condition: template
                value_template: "{{ states('switch.porch_string_lights') in ['on', 'off'] }}"
            then:
              - action: flightday.report_check
                data:
                  source: x_porch_lights_check
                  key: porch_lights_late
                  status: "{{ 'attention' if is_state('switch.porch_string_lights', 'on') else 'ok' }}"
                  title: Porch string lights are on
                  since: "{{ states.switch.porch_string_lights.last_changed.isoformat() }}"
                  morning: false
                  action:
                    label: Turn off
                    domain: switch
                    service: turn_off
                    target: {entity_id: switch.porch_string_lights}
            else:
              - action: flightday.clear_check
                data: {source: x_porch_lights_check, key: porch_lights_late}
          - wait_for_trigger:
              - trigger: state
                entity_id: switch.porch_string_lights

Coffee when up

Staging validation: pending

Reacts to a confirmed “I’m up”, leaving out tests and timeouts.

coffee-when-up/coffee.yaml
- alias: Coffee when up
  triggers:
    - trigger: event
      event_type: flightday
      event_data: {v: 3, action: up, test: false}
  conditions:
    - condition: template
      value_template: "{{ not trigger.event.data.test and trigger.event.data.by != 'timeout' }}"
    - condition: time
      after: "05:00:00"
      before: "12:00:00"
    - condition: state
      entity_id: switch.coffee_maker
      state: "off"
  actions:
    - action: switch.turn_on
      target: {entity_id: switch.coffee_maker}

custom-integration-minimal/custom_components/flightday_example/sensor.py
"""Measure the automation count when Flight Day reports ready."""
from datetime import timedelta
from asyncio import Lock
from homeassistant.config_entries import ConfigEntryState
from homeassistant.exceptions import ServiceValidationError
from homeassistant.components.sensor import SensorEntity
from homeassistant.helpers import entity_registry as er
from homeassistant.util import dt as dt_util

async def async_setup_platform(hass, config, async_add_entities, discovery_info=None):
    async_add_entities([AutomationCount()])

class AutomationCount(SensorEntity):
    _attr_name = "Flight Day example automation count"
    _attr_unique_id = "flightday_example_automation_count"
    _attr_should_poll = False

    async def async_added_to_hass(self):
        await super().async_added_to_hass()
        self._ready_lock = Lock()
        self._checked_at = dt_util.now()
        self._initial_published = False
        # Subscribe first: late setup may have missed the one-time ready event.
        self.async_on_remove(self.hass.bus.async_listen("flightday", self._maybe_ready))
        if any(e.state is ConfigEntryState.LOADED
               for e in self.hass.config_entries.async_entries("flightday")):
            await self._on_ready(initial=True)

    async def async_will_remove_from_hass(self):
        # Deleting the entity in Settings also removes its Flight Day line.
        # A restart or shutdown keeps the registry entry, so nothing is cleared then.
        if er.async_get(self.hass).async_get(self.entity_id) is None:
            await self.hass.services.async_call("flightday", "unregister_integration",
                                                {"id": "example_sensor"}, blocking=False)

    async def _maybe_ready(self, event):
        if event.data.get("action") == "ready":
            await self._on_ready(event=event)

    async def _on_ready(self, initial=False, event=None):
        async with self._ready_lock:
            # A queued ready from before the loaded check describes the same load.
            if event and self._initial_published and event.time_fired <= self._checked_at:
                return
            try:
                await self._publish()
            except ServiceValidationError as err:
                if str(err) != "not_ready":
                    raise
                return  # A reload raced us; wait for its next ready, without polling.
            if initial:
                self._initial_published = True

    async def _publish(self):
        hass = self.hass
        self._attr_native_value = len(hass.states.async_entity_ids("automation"))
        self.async_write_ha_state()
        await hass.services.async_call("flightday", "register_integration", {
            "id": "example_sensor", "name": "Automation count", "provides": ["lines"]
        }, blocking=True)
        await hass.services.async_call("flightday", "post_line", {
            "source": "x_example_sensor", "key": "automation_count",
            "text": f"{self.native_value} automations at Flight Day ready",
            "show": ["home"], "priority": "normal",
            "until": (dt_util.now() + timedelta(hours=24)).isoformat()
        }, blocking=True)

Rules for integration authors

  1. Honest data. Post a line only when you know it’s true. Say “as of” when data is old, and clear lines that stopped being true.
  2. Plain voice. Short, numbers over adjectives, sentence case, no exclamation marks or emoji. “Recycling goes out tonight.”
  3. Quiet nights. Night lines are text only. Integrations never play sound, turn on lights or wake bedroom screens at night.
  4. Warm light. If your automation sets lights in reaction to Flight Day, use the warmest colour temperature.
  5. Thermostat Off is sacred. Never turn a thermostat on from Off in reaction to Flight Day.
  6. Privacy. Lines and checks show on every screen in the house. Use the person field for anything meant for one crew member, and never post credentials, addresses or health data.
  7. Rate. Update a line when it changes, not on a timer.

Getting listed

Community integrations are listed here when they follow the rules above, have a public repository and docs, and are submitted by pull request to the site with a one-line description and a Real or Sample screenshot.

Being listed never means Flight Day runs that code. People install it themselves.
